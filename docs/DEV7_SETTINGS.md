# 安装与设置（当前 dev.16）

dev.15 的可选无识别文字扣血：单人 F7 →「游戏与词库」，联机由服主网页设置。默认关闭，启用后默认 20 秒没有新文字开始每 4 秒扣 2 点生命（1 心）；三个参数可调，保存后立即生效，无需重连。麦克风/配置启用的模型未就绪、故障或处理卡住时，客户端停止识别，服务端暂停判定和此项扣血；底部每约10秒提示，恢复后重新等待20秒。双方更新dev.16后进入世界/服务器就监测，开始/停止不重置健康状态；初始未确认约4秒、短暂异常约2秒确认再提示。未开始玩法不会扣血。等待期间仍暂停判定/扣血。已有配置需手动改0.30、20秒、4秒。规则与验证见 [dev.15 说明](DEV15_VALIDATION.md)，下面保留原有安装及其他设置。

本版为开发测试候选版，提供一个完整离线安装包，并提交代码 PR；不自动部署到玩家游戏目录。以下为手动安装与升级步骤。模型留在游戏缓存，JAR 不内嵌权重，不需要 Simple Voice Chat。

## 现有 PCL 实例升级

当前运行实例目录：`D:\Program\PCL2\.minecraft\versions\1.21.11-VoiceKill`。启用版本隔离时，以它作为下述 `<游戏目录>`；未隔离时查看启动器实际游戏目录。

1. 退出 Minecraft，先将 `mods` 中旧 `voicekill-*.jar` 移到备份目录，再放入 `voicekill-1.0.15-dev.16.jar`。不要同时加载多个版本。
2. 将已按模型清单核对的 `silero_vad.onnx` 放到 `<游戏目录>/voicekill/models/silero-vad/silero_vad.onnx`。
3. 原有 `zipformer-bilingual-small-int8`、`sensevoice-review-int8`、`punctuation-zh-en-int8` 三组模型继续使用；Fabric API、Shriek、Architectury 也继续使用当前兼容版本。
4. 保留原 `config/voicekill.json`，不覆盖词库和设备。F7 →「语音识别」：声学自然断句开、停顿确认 0.6 秒、持续讲话兜底 10 秒、句末音频复核开、离线标点开、词表识别提示开，然后保存并重连。若已有配置关闭了自动开麦，按 F8 手动连接。
5. 输入 `/vk start` 开始。服主设置每轮词和人名，玩家各自设置麦克风、识别与 HUD。

完整离线包中，`.minecraft` 文件夹内部内容按同样结构合入实际游戏目录（版本隔离时不要再套一层 `.minecraft`），4 个模组在 `mods`，4 组模型在 `voicekill/models`。只有首次安装且没有现成配置时才使用 `config-template/voicekill.json`。模板关闭自动下载和 Vosk 回退，包中没有 Vosk 模型。

独立服务端只需同版本 VoiceKill 和这三个前置；无需复制语音模型。每位客户端需要模型。服务端词库从服务端配置/本机网页控制台管理，客户端 F7 不覆盖远程服务器规则。

## F7 统一面板

主菜单和暂停菜单右上也有「VoiceKill 设置」。较小窗口自动按页展示。Esc / 返回丢弃未保存草稿。

| 页签 | 可调内容 |
| --- | --- |
| 语音识别 | 声学自然断句、停顿 0.35～1.5 秒、持续讲话兜底 2～15 秒、句末复核、离线标点、词表提示 |
| 设备与模型 | 模型实时下载进度、F8 设备与连接状态、自动开麦、识别引擎、CPU 线程、自动下载、兼容回退、排查日志、主/句末模型目录 |
| 画面提示 | HUD、实时转写及保留时长/行数、危险词最大宽度/每页行数、背景透明度、物品栏提示换行/宽度/时长/高度 |
| 排行榜 | 显示开关、五个位置预设、横/纵比例滑块、使用示例数据的布局预览 |
| 游戏与词库 | 自定义死亡文本开关/编辑/预览、读音模糊开关/强度、本地每轮词数/人名/高频词配额、换词间隔、智能选词、进服与换词提示；进入本地世界后可打开网页词库管理 |

「保存」立即应用显示设置；识别参数下次重连生效。「保存并重连」会重新初始化模型及设备。F8 切换成功后保存设备，F7 旧草稿不会把新设备改回。

## 显示与处罚

左上危险词最多 20 个，按宽度换行；放不下时轮播分页，不丢弃后面的词。其下方显示本机临时/最终转写，默认保留 6 秒、最多 3 行。危险词和字幕背景各自按当前可见行的实际最大宽度收窄，并计入标题/页码/“识别中”标签；两块保持左对齐，配置宽度仅作换行上限。逐字精确出现的危险词以粉红显示，忽略空格和大小写，保留原始文本排版。

临时文本可被模型修订，只显示、不上传用于处罚。仅最终选定句经服务端统一读音匹配判定（默认开，强度 0.30，范围 0.05～0.75，越大越宽）。粉红属于文字提示，不是处罚证据标记；别名/读音模糊命中未必能在转写中显示成粉红。不将有争议的字母结果一律排除，也不添加昵称专用的谐音补丁。

物品栏上方只接管 VoiceKill 的「本轮危险词：」提示，其他模组/原版 actionbar 不拦截。设置中的提示宽度是换行上限；短提示背景按当前页最宽文字居中，两侧各留 6 像素，不铺满上限宽度。长提示换行，极长时分页并延长展示；排行榜采用归一化位置，分辨率变化时仍留在屏幕内，避让左上词/字幕及右上计时面板。

| JSON 字段 | 默认 |
| --- | --- |
| `autoStartMicrophone` / `speechNaturalBoundary` | true / true |
| `hudTranscript` / `hudTranscriptSeconds` / `hudTranscriptLines` | true / 6 / 3 |
| `hudWordWidth` / `hudWordLines` | 280 / 6 |
| `hudHotbarHint` / `hudHotbarWidth` / `hudHotbarSeconds` / `hudHotbarBottom` | true / 420 / 5 / 72 |
| `hudBoardX` / `hudBoardY` | 1 / 0.5（右中；范围 0～1） |
| `hudPanelOpacity` | 0.4 |

宽度/高度使用 GUI 逻辑像素，随 Minecraft 界面缩放变化。网页控制台仍可管理词库、人名和别名；此面板没有将所有复杂词库编辑器再复制一遍。

## 模型实时下载进度

F7 →「设备与模型」→「模型下载进度（实时查看）」。四个卡片分别显示双语识别、自然断句、句末复核、标点模型的状态、进度条、百分比、已完成/总 MiB、当前文件及文件序号；窗口较小时自动分页。悬停可看完整路径和失败信息。后台下载时画面自动刷新，离开页面不停止下载。

先在 F7 保存路径与自动下载开关，再「保存并重连麦克风」开始实际准备；进度页使用已保存配置，查看页面本身不触发下载。尚未准备的模型显示「尚未检查」，不会把已存在但尚未校验的缓存误报为缺失。关闭的可选模型显示「未启用」。

百分比按固定模型清单的字节总量计算，已经校验的本地文件计入完成大小。100% 只代表字节到齐：校验成功才显示「文件就绪（已校验）」；HTTP/大小/SHA256 失败会明确报错，重新连接后重试。文件就绪与 native 模型加载完成是两个阶段，连接状态仍以 F8 为准。此进度覆盖当前四组模型，Vosk 兼容下载不使用此链路。

本次只编译与定向测试，没有打包或部署。下载链路测试使用本地 HTTP 分段响应验证中途进度、缓存计数、HTTP/哈希失败和重试，不下载真实模型、不打开麦克风；新增界面尚未重新启动 Minecraft 验收。

## 自定义死亡文本

F7 →「游戏与词库」→「自定义死亡文本」。默认开启，使用用户提供的 20 条损友整活文案。支持增删、分页编辑、恢复默认和使用 Alex / qaq 的即时预览；预览不会处罚玩家。点击「应用到设置草稿」返回父页面，再点「保存」应用；直接返回/Esc 放弃该编辑页未应用的更改。

支持 `{player}`（受罚玩家显示名）、`{word}`（本次危险词，粉红色）两个占位符，值按普通文字插入，不作为命令、JSON 或新的占位符再次执行。每次处罚只随机选择一次，聊天和死亡界面使用同一句。最多 32 条、每条 200 个 Unicode 字符；空白/重复项被清理，空列表恢复默认，换行转换为空格。

示例：

```json
{
  "customDeathMessages": true,
  "deathMessageStyle": "custom",
  "deathMessages": [
    "{player} 用一句「{word}」换来了一次重生。",
    "{player} 因为「{word}」荣登言多必失榜。"
  ]
}
```

这是服务器玩法设置。单人世界可以从 F7 修改，保存后供下一次处罚使用；远程服务器由服主修改服务端 `config/voicekill.json` 并重启，客户端自己的模板不会覆盖服主设置。

新文案进入正式死亡消息，遵循原版死亡消息开关和队伍可见性。同时始终保留原来的踩词公告，包含玩家、危险词和识别原文，原文大小写/空格/标点不改写。关闭自定义功能仍保留踩词公告，并使用原版死亡消息。只改变 VoiceKill 处罚的死亡文本；掉落、摔落等其他死亡不使用此模板。处决沿用注册的 generic-kill 伤害类型和 Float.MAX_VALUE，未改识别及匹配规则。

### 风格选择与原文提示

点击编辑页顶部的「风格」切换，选定后应用到草稿并保存：

| 配置 ID | 风格 | 文案数 |
| --- | --- | --- |
| `friends` | 损友整活（默认，用户提供的完整混合池） | 20 |
| `classic` | 经典（原来的文案） | 8 |
| `loot` | 装备与经验 | 4 |
| `voice` | 声带背锅 | 4 |
| `deadpan` | 正经胡说 | 4 |
| `custom` | 自定义混搭，使用 `deathMessages` | 1～32 |

单选预设不会覆盖自定义池；编辑、增删预设中的任一条会自动转入「自定义混搭」。恢复默认会恢复当前预设；自定义模式恢复默认的 20 条整活文案。自定义池为空时使用默认整活池兜底。

处罚时两类信息分别显示，例如：

```text
[VoiceKill] Alex 说出了危险词「qaq」（识别：我刚刚说的是 Q A Q！）
Alex 留下遗言「qaq」，然后安详地爆了一地装备。
```

第一条沿用原有原文公告，第二条为选中风格的正式死亡消息。文案属于娱乐文本，不改变装备掉落、经验或出生点等游戏规则。
