# dev.16 入服即监测与启动误报修复

候选版本1.0.15-dev.16。用户报告`/vk start`瞬间提示麦克风异常，但实际设备正常，并明确要求进入游戏即检查，不等开始玩法才检查。只读核对实例已装dev.15，日志显示Realtek麦克风成功以16kHz mono打开。

旧实现把健康上报和告警检查限制在running=true，开始时清空健康状态，第一条报告未到就允许提醒。首次音频帧还没到也可能被当作麦克风异常。

## 行为

- 进入世界/服务器就持续上报和检查采音、模型状态；不要求先输入`/vk start`。主菜单/断线不弹游戏内提示。
- `/vk start`只开启玩法和处罚、重新给完整等待时间，保留入服后已经确认且仍有效的设备状态；不会重启识别器、清空健康状态或延长旧状态有效期。`/vk stop`停止处罚，状态监测继续。
- 开始新玩法后只接受新会话报告；此前的缓存状态按原到期时间失效，旧报告不能续期。换世界重新初始化、断线和死亡清理对应玩家状态。
- 自动开麦尚未开始、设备正在打开、第一帧还没到统一视为“未确认”，不直接判成麦克风故障。
- 未确认/异常状态仍立即暂停语音判定和无识别扣血；提示单独确认：UNKNOWN持续80tick（约4秒）、其他异常持续40tick（约2秒）后才提醒，之后200tick（约10秒）限频。
- READY到达立即清除待确认状态，即使恢复发生在两次提示检查之间也不沿用旧计时。客户端的旧服务端兼容提示复用同一确认机制。

## 性能

监测只读取现有会话/模型状态，不额外启动识别线程、加载模型或扫描文件。正常每秒1个状态包，内容38字节（不含网络协议头）；状态变化额外上报。原来已在运行的离线识别仍是主要开销。

本机纯健康状态/等待计时模拟，预热2000tick后采样10000tick：10玩家中位0.0007ms/tick、P95 0.0019ms/tick；100玩家中位0.0017ms/tick、P95 0.0072ms/tick。100玩家最大3.1733ms的离群值保留，不宣称零开销。仅计Java状态逻辑，不含Minecraft、网络发送、文字绘制或ASR，不是游戏FPS实测。证据在`.local/diagnostics/dev16/health-timing.jsonl`。

## 更新

要完整使用“进入游戏即监测”，客户端和服务端都更新dev.16；dev.15报文仍兼容，但旧客户端只在玩法开始后上报，不能提供开局前检查。单人更新客户端JAR即可。

默认值不变：读音强度0.30、扣血默认关闭、20秒等待、2点生命/次、4秒间隔。原模型、配置和用户WordBank保留；完整包仍为4模组、4组模型9文件，不含Vosk。
