## 已实现

| 问题 | 修改 |
| --- | --- |
| 同一句的不同候选被错拼成新词 | `SpeechWindow` 分支处理候选，每个包只更新一次历史 |
| 旧危险词从上句话/上一轮残留中触发 | 命中必须包含本次新片段；开始、停止、换词、修改当前词/别名、断开与处决时清理窗口 |
| “哈、哈”被当重复文本丢掉 | 新客户端为最终识别事件附加 UUID；只按事件 ID 去重，连续相同文本保留 |
| 最优结果“才”，备用候选“干”导致单字处决 | 单字危险词只接受最优候选；取消自动生成中文单字谐音，显式手工别名仍保留 |
| `qaq` 谐音被 48 项枚举上限截断 | 按位置的读音规则直接匹配，枚举只用于展示；补充 A 的“爱/艾”读法 |
| 长人名同音字多处变化 | 人名/手动长词可按逐字读音匹配，“豆腐唐包包”可以命中“豆腐汤宝宝”；原有编辑距离容错保留 |
| 录音线程退出但界面仍显示正在录音 | 单次 `CaptureSession` 统一退出和资源释放；设备错误进入 failed 状态 |
| 录音接管时争用设备、共享 native 识别器 | 先停止并等待 Shriek 线程，再开设备；VoiceKill 独占自己的 Vosk Model/Recognizer |
| 固定 16kHz 导致设备被过滤 | 探测 16/48/44.1kHz、mono/stereo 的 16bit PCM，转换成 16kHz mono 后识别 |
| 切换设备无明确反馈 | F8 支持分页、刷新、停止和重新连接；显示输入音量和错误，成功后保存设备 |
| 网页调试直接处决在线玩家 | UI 默认调用 `/api/debug/match` 安全预览；历史 `/api/debug/speech` 仍是会影响玩家的模拟接口 |
| 网页录音设置与实际状态不符 | `/api/audio` 返回状态/设备/格式/错误/音量；POST 异步切换本机设备；独立服务器明确禁用远程设备控制 |
| 13～20 个词在 HUD 中丢失 | 数据包上限由 12 调整为 20，与配置上限一致 |
| 手机控制台横向溢出 | 补齐 12 列区块、网格最小宽度和窄屏换行，错误响应不再静默当作成功 |

## 已知边界

- 第一阶段保留 Vosk；dev.2 已默认改用双语 Zipformer，但模型把“才”识别成“干”时，文本侧仍无法可靠还原原话。
- Java Sound 的设备/权限/驱动差异及 macOS native 架构支持必须实机验证；代码中的格式回退不保证所有硬件可用。
- 已只读检查 Shriek 1.1.22+fabric 内嵌的 `libvosk.dylib` 和 JNA `libjnidispatch.jnilib`：二者均为包含 x86_64、arm64 的通用 Mach-O 文件。因此不能直接将 MacBook Air 的反馈归因于“包里缺少 arm64 库”；实际加载和权限仍未验证。
- 断句窗口限 5 秒、每条路径保留 64 字，最多 32 条候选路径；长停顿或极多歧义可能仍漏判。
- 旧 Shriek 内部 API 仍用于停止其监听及准备模型，升级 Shriek 前需重新核对字节码。
- 切换会重新加载识别模型；发生超时会拒绝开启第二条录音线程，不强行关闭仍被使用的 native 资源。
- `stop` 停止玩法；需要停止物理采音时使用 F8 的“停止录音”。识别文本日志仍由 `logSpeech` 控制。
