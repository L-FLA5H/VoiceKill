# dev.9：保留完整初识，约束游戏词读音纠错

## 问题和判定

dev.8 把已接受的复核作为最终句，修复了“原文好吃的、复核为英文，仍因吃的死亡”的同段误杀，但复核本身也会丢字。此次保留两份证据，在句末选择阶段判断是否真有理由撤回初识；不会简单使用“任一候选命中就处罚”。

- 孤立 3～8 位字母序列，复核仅少一个尾字母且前缀完全相同：保留完整初识，例如 QAQ / QA。
- 孤立中文单字，复核仅改为同音字（文字读音去声调）：保留初识，例如干 / 赶；才 / 干不属于同音，仍不能凭复核新增“干”的处罚。
- 完整四字及以上游戏名，复核恰好少一个尾音节且剩余音节完全相同：保留完整初识；不能反向补全本来就残缺的初识。
- 初识是中英文字，复核却跳到非汉字/拉丁文字（如“干”被改为日文 `が`）：不接受超出中英识别范围的改写。原模型仍保持自动语言识别，以支持中英同句。
- 其他稳定复核仍可撤回初识；“好吃的 / how much the shirt is”和“ABC / amc”不会因初识含有危险词而恢复处罚。

保留后，最终字幕、传输候选和判定使用保留的初识；日志仍记录被拒绝的复核及原因 `primary-retained` / `unsupported-script`。不把这种不完整复核标成完整复核确认，也不会增加一次等待。正常新增复核仍有两次条件稳定性检查，属于同一模型两次处理，不是独立投票。

## 通用游戏词读音层

2270 个 4～24 字 Minecraft 名称，来自固定的 1.21.11 官方中文语言文件，包含物品、方块、生物、群系、附魔和效果。整个词库均参与竞争，和本轮危险词无关；没有逐个追加截图错字别名。

同音替换须保留完整音节数，至少一个相同汉字。经复核确认时，允许整词中至多一次 n/l 或 an/ang、en/eng、in/ing 差异，且至少两个相同汉字。两个变化、缺音节、跨标点/跨事件补全、等分歧义均拒绝；实际存在的其他游戏名优先，不能把“红石比较器”改成“红石中继器”，包括它出现在完整句子中的情况。

接受的最终游戏词还需有初识支持：初识同样指向该完整词，或者最终词完整同音且原文同长窗口至少 N-2 个音节一致、有字面锚点、不是另一个合法游戏词。口音匹配不能走后者的宽松支持路径。

覆盖的文字回归包括：

| 原始 / 复核转写 | 规范游戏词 | 条件 |
| --- | --- | --- |
| 红十种记起 / 红十种记起 | 红石中继器 | 完整同音 |
| 莫隐之夜 / 莫影之眼 | 末影之眼 | 完整复核同音且原始有支持 |
| 下届之星 / 下界之心 | 下界之星 | 已确认、一次鼻音差异 |
| 僵尸朱林 / 僵尸朱林 | 僵尸猪灵 | 两个识别器一致也能传递确认 |

“末影之夜”不会因“末影之眼”在危险词里而补成它，“海洋之心”不会向“下界之星”靠拢。高频/智能来源不走新增游戏读音处罚路径；单字、高频词既有严格规则和显式手工别名保持。最终字幕与统计使用同一受支持的规范游戏名，公告继续保留原始识别原文。临时字幕仍不处罚。

## 数据与依赖

- 官方语言资产 SHA1：`daf8df119618b33ad7476a6be4ac2eadc802fd93`，来源和元数据在 `src/main/resources/voicekill/game-terms-zh-cn.json`。
- 26711 字读音由 ICU4J 77.1 的 Han-Latin 离线生成，固定 JAR SHA256 和读音表 SHA256 随词表记录；运行时只读取小型 JSON，不增加 ICU 运行时依赖，也不新增模型或联网服务。
- 生成工具：`tools/build-game-vocabulary.py --assets-dir <Minecraft资源目录> --icu-jar <ICU4J-77.1.jar>`，调用 `tools/generate-pinyin.jsh`。Unicode 许可与 Minecraft 资产归属声明一并提供。
- 一字只使用一个默认读音，不能处理所有多音字；这是受约束的词表校验，不是语义模型理解句子。

## 安装与兼容
