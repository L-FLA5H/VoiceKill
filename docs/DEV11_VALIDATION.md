# dev.11：长时间没有识别文字时持续扣血

## 使用

默认关闭，避免更新后直接改变原玩法。单人按 F7 →「游戏与词库」开启「未识别到文字时持续扣血」；联机由服主在网页控制台「未识别到讲话时扣血」设置，普通客户端不能修改服务端规则。保存后立即生效，无需重连麦克风。

| 配置 | 默认值 | 范围 |
| --- | --- | --- |
| `silencePenaltyEnabled` | false | 开 / 关 |
| `silenceTimeoutSeconds` | 30 秒 | 5～600 秒 |
| `silenceDamageAmount` | 2 点生命（1 颗心） | 0.5～20 点 |
| `silenceDamageIntervalSeconds` | 5 秒 | 0.5～60 秒 |

超时后的第一次扣血在等待期结束时发生，以后按间隔扣血。实时转写出现不同的识别文字，或收到有效的最终识别句，都会停止当前连续扣血并重新等待完整的超时周期。一直不变的旧临时文字、空白、标点、原始麦克风音量不会刷新计时；独立的两句相同识别原文仍算两次有效识别。

仅 `/vk start` 后对生存/冒险玩家生效；未开始、停止、创造、旁观、死亡、离线时不扣血。开始游戏、复活/重新加入、变为适用模式后都重新等待。修改此规则也重新等待，换词不重置。时间按服务端 tick，暂停不计时，卡顿不补扣多次。扣血可以致死，实际死亡才计入榜单，不把每次扣血算成死亡；使用独立的死亡原因，不声称玩家说了危险词。

麦克风关闭、模型失败或仅有声音却没有识别文字，在开启此玩法后也会超时。原四组模型继续使用；无需重置词库、麦克风和旧配置。

## 实现

- `RecognitionSilence` 用服务端 tick 管理每名玩家的独立截止时间，规则变动/停止/断线清理旧状态。
- `RecognitionActivity` 仅识别新的文字变化和最终句事件，最多每秒发一个活跃通知，未发送的过时文字不会在长时间阻塞后补发；会话变化隔离旧状态。
- 新增可选 C2S `recognition_activity`，只包含当前会话 UUID，不包含待匹配文本。服务端检查会话与玩家状态，临时结果不参与危险词匹配、公告或词频。有效最终句仍走原来的 Shriek 通道，并在完成去重/轮次检查后重置计时。
- 自然模式沿用已有实时转写；原端点 Zipformer / Vosk 兼容路径补齐已有模型临时输出的透传，未改变模型、解码参数、最终候选或判定门槛。
- 独立的 `voicekill:silence` 伤害类型按配置数值执行，附加自身的绕过盔甲、效果和受伤冷却标签，使短间隔和配置量正常工作；不替换原版标签，不修改危险词处罚使用的 generic-kill。吸收生命及其他模组的伤害钩子仍走原版伤害流程。
- F7 新规则属于服务端配置，不进入客户端设置的覆盖白名单；网页复用 `/api/config` 的四个同名字段，浮点非法值和越界值统一钳制。网页拖动时保留正在编辑的值，保存失败不显示成功。

124 项 JUnit 和 `./gradlew.bat test build -x deployToGame` 通过。覆盖等待期、连续间隔、识别后停止扣血并重新等待、玩家独立、死亡/不适用/断线隔离、规则变化、跨轮不重置、卡顿不连扣、无文字/旧临时字串不保活、重复最终句保活、会话隔离、客户端草稿不覆盖服务端规则、通知编解码，以及通过 Minecraft `DamageType.DIRECT_CODEC` 校验伤害类型定义。

原生 Zipformer + Silero 使用原连续讲话 WAV，SHA256 `961b207827d47272fc713ee990dfdafd0ddd14f906dbfa71f23959a8ddcc64f2`，仅在内存追加 8 秒全零静音，测试设置为 5 秒等待、1 秒扣血间隔：

- 首次实时识别文字：输入音频 0.76 秒；首次最终句：10.36 秒。
- 连续讲话时每秒有新的识别活跃通知，没有因为一句话超过 5 秒而提前扣血。
- 最后有效识别在 21.76 秒；第一次扣血判定为 26.76 秒，之后 27.76、28.76 等每秒一次。
- 这是加速模型/计时集成回放，不是真人麦克风、实际玩家生命值或游戏端到端延迟测试。证据 `.local/diagnostics/dev11/silence-replay.json`，入口 `RecognitionSilenceReplay`。
