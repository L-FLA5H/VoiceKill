# dev.15 自适应背景、语音故障保护与默认参数

候选版本 1.0.15-dev.15，验证日期 2026-10-21。本版同时处理左上背景空白、设备/模型故障仍扣血，以及新的玩法默认值。

## 背景按实际文字自适应

危险词按当前页可见行和标题（含页码）测量；字幕按当前显示行和“你说的话 / 识别中”标题测量，不让已滚出显示区的旧行撑宽。两块独立收窄，保持左侧位置和留白。配置宽度只作换行上限，长内容继续换行/分页。“未开始”提示同步收窄，物品栏继续居中。

三块共用 Minecraft 字体的像素测量。左上两块返回实际绘制 Rect，排行榜避让使用实际面板范围，F7 标签明确为最大宽度。

## 故障暂停识别与无识别文字扣血

- 设备未连接、打开失败、采音退出，配置开启的模型加载中/加载失败/运行报错，以及采音或识别长时间无进展，均暂停该玩家的识别输出、语音判定与无识别文字扣血。其他玩家继续正常游戏。
- `CaptureSession` 未就绪时排空输入而不调用识别器；故障发生在句末模型执行中时，返回的备用原文也不发布。恢复或采音中断后丢弃旧音频，不拼接故障前后的碎片。主线程排队超过3秒的旧结果也丢弃。
- `SentencePostprocessor` 记录实际运行异常，`EnhancedDecoder` 透传失败；配置启用的复核/标点模型也必须就绪。主动关闭的模型不纳入就绪条件。失败后修复文件或参数，再按F8/F7重连；不静默使用降级识别继续处罚。
- 客户端每秒及状态变化时通过 `recognition_health` 发送游戏会话UUID和固定状态码，不发送音频、转写、设备名或异常详情。3秒无采音/识别进展视为卡住；服务端健康状态有效期80tick（约4秒），未知或过期也暂停。
- 服务端每200tick（约10秒）仅向问题玩家在底部提示，例如“模型可能出现问题，可能无法正常游戏（已暂停识别/扣血）”。F8与网页也显示暂停原因；未开始游戏不反复提示。
- 恢复后重新给完整等待时间，不补扣故障期间的血。正常健康状态续期不算说话，不刷新无新字等待；正常低音量/静音且采音、模型仍工作，不作为故障，仍按原规则等待新识别文字。
- 停止重开、断线、玩家死亡及会话变化清理旧状态；过期会话的状态报告不能恢复处罚。服务器不接受未知健康状态玩家的识别结果，因此旧客户端也处于保护暂停，而不是继续扣血。

## 默认参数

| 项目 | 默认值 |
| --- | --- |
| 读音模糊开关/强度 | true / 0.30（原0.35） |
| 无识别文字扣血开关 | false |
| 等待时间 | 20秒 |
| 每次伤害 | 2点生命（1颗心） |
| 连续扣血间隔 | 4秒 |

代码默认、非法数值回退、网页初始值和完整包模板一致。已有玩家/服务器配置不会覆盖，需在F7「游戏与词库」或服主网页手动改0.30、20秒和4秒。

## 验证

`./gradlew.bat test build -x deployToGame`：142项JUnit通过，remapped JAR构建成功。新增10项测试覆盖：加载/故障时不执行推理；恢复丢弃旧音频；句末模型报错不泄露备用原文；活线程无采音进展判为异常；服务端未知/过期暂停；健康状态续期不能逃过正常扣血；恢复无旧债；玩家与游戏会话隔离；底部提醒限频；状态包固定编码及非法值拒绝。

Playwright在独立合成网页夹具验证默认0.30/20秒/4秒，保存请求和刷新后回显一致，模型加载中显示“识别/无识别扣血已暂停”，390px无横向溢出，运行中无浏览器错误。夹具已停止；这些是合成数据，不是实际游戏或麦克风。

本次没有启动Minecraft目视验收新背景/底部提示，也没有部署到玩家实例或修改运行中的配置/存档。正常设备静音与系统静音/硬件静音有时都会返回零PCM，仅凭音量无法区分，因此保护依据采音进展、设备错误及模型运行状态，不用零音量豁免讲话规则。

## 安装与兼容

客户端与服务端都必须更新dev.15以使用故障保护，单人世界更新客户端即可。旧服务端无法执行新的健康保护，只更新客户端不能防止旧服务端扣血；旧客户端连接新服务端会因状态未确认而暂停判定。四组模型文件不用更换。

完整离线包仍包含四模组、四组模型九个文件，不含Vosk；模板禁用回退及自动下载，用户WordBank按字节保留。原安装教程仅同步必要的默认值和兼容说明。
