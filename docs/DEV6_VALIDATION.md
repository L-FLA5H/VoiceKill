# dev.6：完整句设置与指定输入设备修复

## 完整句优先的配置

用户实玩反馈 5 秒硬上限会切断一句话，并选择将连续讲话上限改为约 10 秒。新配置默认 `speechMaxUtteranceSeconds=10.0`、`speechEndpointSilenceSeconds=0.6`；已有客户端配置必须修改这两个字段并重启，替换 JAR 不会覆盖已有数值。现有 dev.5 已支持这些参数，模型无需更换。10 秒预算从首次出现非空识别假设开始；静音可提前结算，持续说话仍有硬上限，推理/网络/游戏耗时另计。

0.6 秒是声学停顿等待，不是语义句号检测。它降低短暂换气导致的拆段概率，也会比原来 0.35 秒设置多等待约 0.25 秒。长于上限的无停顿讲话仍会被拆开；换轮词表更新时的旧段丢弃策略保持不变，不允许旧词表继续影响新一轮。

回放工具现在可显式设置 `-PreplayMaxUtteranceSeconds=10` 和 `-PreplayEndpointSilenceSeconds=0.6`，同时将相同上限传给句末 PCM 缓冲，并在报告记录实际参数。旧回放命令仍默认使用历史 5 秒 / 0.35 秒，避免悄悄改变已有基线。

## 指定输入设备失败

用户报告：耳机物理麦克风一直可用，指定 `耳机 (JBL TUNE520BT)` 时出现“没有支持的 PCM 格式”，设置系统默认麦克风后选择默认输入成功。

代码中的可复现问题：设备列表只列输入设备，按名称打开却从所有 Mixer 中取第一个同名项，输出设备可能遮住正常输入；同名的多个输入也会静默取首个。修复后，枚举和按名称打开都先筛选可录音输入，再做精确/唯一子串匹配。同名输入无法区分时拒绝猜测，提示在系统区分名称或使用默认输入；显式设备失败不会静默打开其他麦克风。

补充 8kHz 单/双声道 PCM 探测，并读取驱动明确报告且 Java Sound 可以转换的原生格式，仍统一转换为 16kHz mono。默认输入路径保持原有系统默认选择方式。没有特判 JBL 名称，没有放宽文字匹配。

回归测试通过注入 Java Sound 设备目录，执行真实 `AudioCapture.open` 路径，重现同名输出/输入、8kHz 通话输入、32kHz 驱动声明格式、歧义输入和不静默换麦。合成 PCM 转换测试同时覆盖新增的 8kHz 格式；不打开物理麦克风。旧实现的前三个选择测试均失败，修复后通过。

## 被拒绝的设置

同时尝试了 0.65 秒的停顿等待：可将 450ms 人工换气样本合并为一段，但原有 tofu-split 拆读样本由命中变为漏判，因此没有采用。0.6 / 0.55 / 0.5 秒均保住该拆读命中，人工换气仍是两段；最终选 0.6 秒。句中停顿可能被拆段，此次不宣称具备语义句号检测能力。

## 回放结果

| 句子边界样本（实时） | 原 5 秒 / 0.35 秒：段数 | 新 10 秒 / 0.6 秒：段数 |
| --- | --- | --- |
| complete-sentence | 2 | 1 |
| breath-in-name | 2 | 2 |
| complete-negative | 2 | 1 |
| silence | 0 | 0 |

7.57 秒连续句和 6.69 秒连续句由两段变为一段。450ms 人工换气仍是两段，未改善其漏判；没有将它计为新增命中。

| 同组能力回放 | 命中 / 应触发 | 其他误触发 / 负例检查 |
| --- | --- | --- |
| 原组 22 段 | 17/21 | 0/89 |
| 额外近邻 14 段 | 0/0 | 0/70 |
| 逐字母 49 条 | 21/24 | 1/417 |

相同 WAV 哈希逐项比较：旧命中丢失 0、新增误触发 0；字母组仍有原先 MC → ABC 的 1 次误触发。负例组与字母组每段最多一个结果；原组相邻结果输入间隔最大 1.4 秒，这三组的加速墙钟与音频时钟均不会跨过 5 秒历史过期门槛，已检查计分分支一致。能力回放不用于延迟结论。

24 秒连续讲话样本仍持续结算，首次最终文本约在开口后 11.12 秒，相邻最终文本间隔最大 10.39 秒；目标命中，其他误触发为 0。10 秒是输入音频预算，另有首词、分块和复核耗时。


加速回放的匹配窗口现在使用输入音频时间，避免把数秒音频压到几百毫秒后错误延长服务端的 5 秒跨段历史。人工换气样本在加速回放曾出现跨段编辑距离“命中”，实时回放证明该历史实际已过期；最终结果以实时句子/连续讲话检查及计时分支一致性验证后的原组能力回放为准，不据旧加速分数宣称新增命中。生产匹配器与 5 秒历史窗口没有修改。

## 交付与限制

匹配器、候选来源限制、字母复核、离线标点及模型清单均保持不变。无 Vosk 模型安装包仍保留用户提供的 WordBank，模板关闭 Vosk 回退和自动下载；已有游戏配置只调整本次断句的两个参数，其他设置不覆盖。

54 项 JUnit 测试通过，`test build -x deployToGame` 构建成功，未部署到游戏目录。所有音频回放是合成诊断，不能证明真人完整句准确率或 JBL 实机修复。具体 JBL 设备需要当事玩家使用新版 JAR 再选择设备复测；暂时可以继续使用已经证实可用的系统默认输入。

## 复现命令

```powershell
.\tools\generate-sentence-speech-corpus.ps1
python tools/prepare-speech-corpus.py .local/diagnostics/sentence-profile/corpus
.\gradlew.bat replayNicknames -x deployToGame '-PreplayEngine=enhanced' '-PreplayRounds=1' '-PcorpusDir=.local/diagnostics/sentence-profile/corpus' '-PreplayMaxUtteranceSeconds=10' '-PreplayEndpointSilenceSeconds=0.6'
```

原始语料已存在时不要重新生成或覆盖。模型准备步骤沿用 [dev.5 文档](DEV5_VALIDATION.md)。其他回放参数和计时限制保持一致；新增句子语料用于证明 5 秒强制截断，不能作为真人准确率。
