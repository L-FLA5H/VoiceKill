# VoiceKill

> 历史交接资料：本文件保留开发包原说明，其中选词顺序、设备重连描述等可能反映旧实现。
> 当前默认值、运行结构及验证边界以 [项目结构与运行机制](ARCHITECTURE.md) 和源码为准。

> 每轮随机放 5 个危险词，说到任意一个就当场暴毙。
> 词库是**玩家真会说的话**（「小白」「吃的」而不是「骷髅」「生猪肉」），
> 屏幕上四角常驻显示，还有言多必失榜。

Minecraft **1.21.11** / Fabric。语音识别用 **Shriek**（Vosk 离线识别），
识别结果由 Shriek 走它自己的网络通道送到服务端，服务端判定后直接 `player.kill()`。

五个部分：

1. **服务端判定** —— 说到本轮任意一个危险词（或它的谐音）就 kill
2. **智能选词** —— 每轮结束时统计上一周期谁说得多什么词，下一轮从里面挑
3. **四角常驻 HUD** —— 危险词 / 倒计时 / 言多必失榜 / 最近识别
4. **网页控制台** —— 浏览器里实时改词、改词库分类、配谐音、选麦克风（`http://127.0.0.1:38471/`）
5. **联机包** —— 桌面 `VoiceKill联机包\`，别人拿去就能装

| Fabric Loader | **0.17.3+**（见下方说明） | 本模组只声明 0.16.0，但实际卡在 Fabric API |
| Fabric API | **0.141.6+1.21.11** | |
| Shriek | **1.1.22+fabric** | 语音识别本体，**客户端和服务端都要装** |
| Architectury API | **19.0.1+fabric** | Shriek 的前置，缺了 Shriek 直接罢工 |
| Java | **21** | 构建和游戏都要 |

> 四个模组（VoiceKill + Fabric API + Shriek + Architectury）全丢进 `mods` 文件夹。
> **Shriek 是「客户端 + 服务端」双端模组**，单人游戏也一样要装。
>
> 给别人的话直接用桌面上的 **`VoiceKill联机包`**，里面有这 4 个 jar + 中文模型 + 安装说明。

### 关于 Fabric Loader 的最低版本

本模组的 `fabric.mod.json` 里写的是 `fabricloader >=0.16.0`（不额外加门槛），
**但实际能跑的最低版本是 0.17.3**，因为：

| 模组 | 自己要求的最低 Loader |
| --- | --- |
| VoiceKill（本项目） | 0.16.0 |
| Shriek 1.1.22 | 0.16.2 |
| **Fabric API 0.141.6+1.21.11** | **0.17.3** ← 真正的瓶颈 |

Fabric 的规则是「取所有模组要求里的最大值」，所以装 0.16.x 会直接拒绝启动，
报错长这样（我拿 0.16.14 实测过）：

```
模组 'Fabric API' (fabric-api) 0.141.6+1.21.11 需要 模组 'Fabric Loader' 的 0.17.3 及以上版本，
但已经安装了的版本 0.16.14 不对！
```

1.21.11 想低于 0.17.3，除非不用 Fabric API —— 而不装 Fabric API 的话
Shriek 和 Architectury 都起不来。所以这个下限改不了。

## 3. 网页控制台

进游戏（单人世界 / 自己的服都行）之后，浏览器打开：

```
http://127.0.0.1:38471/
```

页面长这样：`docs/console-desktop.png`（桌面）、`docs/console-mobile.png`（手机）。

**能干什么：**

| 区域 | 操作 |
| --- | --- |
| 顶部一排词 | 本轮全部危险词，每个带来源标签（智能/高频/随机/手动），点 `×` 单独删掉 |
| 「往本轮加一个词」 | 手动塞一个词进去（组满了就不给加） |
| 下一轮危险词 | 多个词用空格/逗号隔开，留空 = 自动组一组 |
| 选词设置 | 智能概率、**每轮几个词**、**高频地狱词几个**、轮换间隔，拖动就生效 |
| 本周期高频词 | 点 chip = 设为下一轮；点 `+` = 加进自定义词库 |
| 上一周期高频词 | 智能选词的来源，看看它下一轮会从哪儿挑 |
| 词库 | 五个分类（自定义 / 人名 / 口语 / 正式 / **高频**），可搜索、可增删 |
| 换词历史 | 最近 20 轮，每轮一组词 |
| 模拟输入 | 打一句话喂进管线，**不用真的对着麦克风吼就能测** |

**安全**：服务只绑 `127.0.0.1`，局域网和外网都访问不到。想改端口就改配置里的 `webPort`。

**注意**：网页是「读快照 + 排队写」的 —— 页面每 1.5 秒拉一次状态，
你的点击会排进服务端逻辑线程执行，所以怎么点都不会把游戏状态搞坏。

## 4. 一组词是怎么凑出来的

每轮换词时，按这个优先级把 `wordsPerRound`（默认 5）个位置填满：

| 顺序 | 来源 | 说明 |
| --- | --- | --- |
| 1 | **手动指定** | 网页上预定的下一轮词，原样优先放入 |
| 2 | **智能选词** | 上一周期的高频词，**按频次加权随机**，每个位置独立判 `smartPickChance` 概率 |
| 3 | **高频地狱词** | 固定 `highFreqPerRound` 个（默认 1），从「我/你/他/什么/就是…」里抽 |
| 4 | **随机词库** | 剩下的位置从三层词库里随机补满 |

举个例子，默认配置下典型的一组是：
`苦力怕(智能) / 钻石(智能) / 完了(高频) / 三叉戟(随机) / 附魔书(随机)`

**为什么不取最高频的那个词？** 因为每轮都是同一个词，观众两分钟就腻了。
加权随机能让热门词更容易出现，但每轮组合都不一样。

**智能选词不再只看上一轮**：候选词按「上一轮 ×3 + 整局累计 ×1」加权。
也就是说开局聊过一次的词不会只活一轮 —— 整局下来反复出现的词，出现概率会越来越高。

**为什么高频词要定额投放？** 如果直接混进随机池，可能出现一组 5 个全是
「我你他」的情况 —— 一开口就没，反而没节目效果。定额 1 个刚好：躲不掉，但还有余量。

### 什么词有资格当危险词

不是所有高频词都能上，要过三道筛：

1. **词库里认识的词** —— 直接用
2. **词库不认识的词**（玩家临时聊出来的）—— 必须**重复出现 2 次以上**，
   否则大概率是 n-gram 切出来的碎片（「天又被苦」「苦力怕炸」），拿它当危险词根本没人说得出来
3. 首尾是虚字的（「这个苦力」「个苦力怕」）—— 直接扔

### 中文分词的两个关键处理

Vosk 的中文输出是「苦 力 怕」这种**带空格**的形式，所以：

- **空格不切断中文**（只切断英文），「苦 力 怕」会被拼回「苦力怕」
- 取 2~4 字滑动 n-gram 统计，然后**压掉碎片**：
  - 「苦力」是「苦力怕」的子串且频次不更高 → 扔掉
  - 首/尾是虚字的（「这个苦力」「个苦力怕」）→ 扔掉
  - 频次低于 2 的（当有明显高频词时）→ 扔掉

不这么处理，榜单上全是「我这个」「今天又」这种垃圾。

## 5. 词库分四层（重点是"口语"）

| 层 | 来源 | 说明 |
| --- | --- | --- |
| 自定义 | 配置里的 `dangerWords` + 网页添加的 | 你说了算 |
| **人名** | 配置里的 `nameWords` | 每轮固定 `namesPerRound` 个 |
| **口语俗称** | 代码里的 172 个「小白 / 吃的 / 镐子 / 挖矿…」 | **主力**，因为大家真这么说 |
| 正式名 | 67 个「骷髅 / 末影珍珠 / 不死图腾…」 | 少数人会这么念，留着 |
| 高频词 | 内置 **253 个** + 你自己加的 | 定额投放，说出来必死 |

> **不再自动收集在线玩家 ID** —— 没人会念游戏 ID。人名只来自你在网页「人名」分类里手填的词。

### 为什么口语层是主力

实测结论：**没人会在跑图的时候喊「生猪肉」「骷髅」**。
大家喊的是「小白」「吃的」「镐子」「这破图怎么这么大」。

所以词库从「物品栏名字」换成了「玩家嘴里的话」：
- 生物：小白（骷髅）、小黑（末影人）、姜丝、毒蜘蛛、盲僧（监守者）、六角恐龙
- 资源：钻石、铁锭、红石、粘液球、腐肉、火药
- 吃的：吃的、喝的、面包、金苹果、土豆、炖菜
- 行为：挖矿、下矿、刷怪、掉虚空、摔死、跑图、联机、附魔、召唤

这些词的特点：**说出来不奇怪，但也不会闲聊时脱口而出** —— 正好。

### 高频词也能自己改

内置 **253 个**（我/你/他/的/了/就是/完了/卧槽/离谱/麻了/寄了/救命/搞什么…），1.0.14 从 142 扩上来的。网页「高频」分类里：
- 点 `×` → 禁用某个内置词（记进 `highFreqDisabled`）
- 底部输入框加词 → 追加到 `highFreqExtra`

两个列表合起来就是实际生效的高频词表，`highFreqWords` 可以在 `/api/state` 里看到。

### 人名为什么要单独一层

「谁的名字被念到谁死」是最有节目效果的玩法，而且人名（尤其英文 ID）几乎不可能
被随机说中，所以必须**定额投放**：`namesPerRound`（默认 1）保证每轮至少有一个。

人名词 = 你在网页「人名」分类里加的 + 当前在线玩家的名字（自动跟随进出）。

> 用**中文模型**时，内置词库里的纯英文词会被自动剔除（说 redstone 中文模型认不出来）。
> 自定义词和高频词不剔除 —— 那些是你自己加的。

> 注意：高频词同样在词频统计的停用词表里（统计时忽略，否则榜单全是「我」），
> 但作为**危险词**匹配时完全不受影响 —— 两套逻辑互不干扰。

## 5.5 谐音别名（解决「ad 被识别成哎弟」）

这是实测最容易踩的坑：玩家叫 `ad`，Vosk 中文模型**不可能**输出 "ad"，
它只会吐「哎弟」「诶地」「阿德」。

做法：把英文缩写按字母拆开，每个字母映射到 Vosk 常见的几种识别结果，做笛卡尔积。

`ad` 自动得到 **25 个变体**：

```
诶地 诶弟 诶的 诶底 诶迪 诶滴 哎地 哎弟 哎的 哎底 哎迪 哎滴
阿地 阿弟 阿的 阿底 阿迪 阿滴 啊地 啊弟 啊的 啊底 啊迪 啊滴
```

说到其中任何一个，都算踩中 `ad`。实测日志：

```
（模拟输入）：哎 弟 你 在 干 嘛
命中危险词「ad」，但当前没有玩家可处决（只做匹配验证）
（模拟输入）：阿 德 快 跑
命中危险词「ad」，但当前没有玩家可处决（只做匹配验证）
（模拟输入）：今 天 天 气 不 错     ← 不命中
```

**手动补充**：网页「谐音别名」里，点一下本轮的词 → 输入别名 → 添加。
配置里是 `aliases`：

```json
"aliases": { "ad": ["阿德", "哎地"] }
```

1.0.13 起多支持一种：**英文夹中文**（`p老板` / `ad哥` / `打q`），
只把里面的字母换成中文读音，汉字原样保留：

```
p老板  →  屁老板 / 批老板 / 皮老板 / 劈老板 / 匹老板
```

纯英文的上限也从 24 提到 48，`qaq` 这种三字母能铺满（`扣诶扣` / `扣诶球` / `秋诶秋` …）。

限制：自动生成只对 **≤5 个字符的纯英文/数字** 生效（再长组合就只是前几种候选的排列），
更长的英文名、或者模型根本听不出的词（`qaq` 被识别成一整串别的字），只能手动在网页上配别名。

> **老实说**：Vosk 的**中文小模型**对英文单词本来就很弱，`p老板` 能救是因为字母被读成
> 单个汉字；`qaq` 这类如果模型直接吐出一串完全不相干的字，靠变体也救不回来。
> 真要玩英文，见 7 节换成英文模型（`vosk-model-small-en-us-0.15`）。

### 5.5.1 模糊匹配（中文人名更容易命中）

除了谐音，还加了**编辑距离**兜底：`你好呀装装` 被识别成 `你好呀中中`、`你好呀庄庄` 都算中。

规则（宁可漏判也不误杀）：

| 条件 | 说明 |
| --- | --- |
| 只对**人名**和**手动指定**的词生效 | 「小白」「吃的」这种口语词一律精确匹配，不然「小黑」都要算成「小白」 |
| 长度 ≥ 4 才启用 | 短词误伤率太高 |
| 长度 4 允许差 1 个字，长度 ≥5 允许差 2 个字 | 不会再放宽 |
| 等长滑窗 | 长句里逐段比，不会因为句子长把差异稀释掉 |

实测：

```
你 好 呀 中 中  → 命中「你好呀装装」
你 好 呀 庄 庄  → 命中「你好呀装装」
今 天 天 气 真 不 错 → 不命中
```

### 5.5.2 同音字（「她」说成「他」也要中）

Vosk 中文模型**不会**输出 `ta` 这种拼音，它输出的是**另一个同音汉字**。
所以 `她` 被识别成 `他` / `它` 时，按字面匹配永远不中。

现在内置了一张 **185 条**同音字表，逐字替换生成变体：

| 类型 | 例子 |
| --- | --- |
| 高频虚词 | 她→他/它/塔，的→得/地/底，是→事/市/式，在→再，那→哪/纳 |
| 人名常用字 | 装→庄/中，晴→青/清/情，明→名/鸣，小→晓，伟→维/卫，静→净/敬 |

规则：一次只替换**一个位置**（不跑全组合，避免爆炸）；
两个位置同时错的情况留给编辑距离去兜（长度 ≥4 时最多差 2 个字）。

实测：

```
她 在 本轮   + 说「他 今 天 又 来 了」 → 命中「她」
她 在 本轮   + 说「它 在 那 边」     → 命中「她」
```

### 5.5.3 被拆成两截的词（「秒切」→ 秒 + 切）

Vosk 遇到短停顿就**断句**，`秒切` 这种词经常被切成 `秒` 和 `切` 两个独立结果、分两次发上来，
单独匹配任何一个都中不了。这就是「明明说了却不判定」最常见的原因。

解法：服务端给每个玩家保留**上一句最后 8 个字**，把这一句拼上去再匹配。

| 情况 | 结果 |
| --- | --- |
| 「秒」…（0.4 秒）…「切」 | 拼成 `秒切` → **命中** |
| 「秒」…（6 秒）…「切」 | 超过 5 秒窗口，不拼 → 不命中（避免误杀） |
| 玩家被处决后 | 立刻清空尾巴，避免复活瞬间再被带走 |

日志里这类命中会带一行 `跨句拼接后命中：xxx → 危险词「yyy」`，方便排查。

---

### 5.5.4 多候选识别（1.0.14）

小模型经常把「秒切」听成「秒且」。但 Vosk 其实**知道**正确答案，只是排在第二、第三。
1.0.14 起让 Vosk 每次返回前 **3 个候选**，第二、第三候选也参与匹配：

```
[VoiceKill] 第 2/3 候选「秒 切」命中危险词「秒切」（最优结果是「秒 且」）
```

实现上没有硬依赖 `org.vosk`（走反射调 `setMaxAlternatives` / `acceptWaveForm` / `getResult`），
拿不到就自动退回单结果模式，不会把识别搞挂：

```
[VoiceKill] 已开启多候选识别（每次最多 3 条）      ← 正常
[VoiceKill] 多候选模式不可用，退回单结果：xxx      ← 退化，但还能用
```

候选用一个不可见分隔符跟主结果打包在同一个网络包里：
**第一段进词频统计和日志，全部参与匹配** —— 统计不会被候选污染。

## 5.6 屏幕四角常驻（替代 actionbar）

以前换词只飘一下 actionbar，看一眼就没了。现在改成**四角常驻**：

```
┌──────────────────────────────────────────────┐
│ 本轮危险词                      12s 后换词    │
│ 小白 · ad · 岩浆 · 吃的 · 哦 · 苦力怕         │
│ 铁傀儡 · 挖矿 · 就是 · 完了 · 土豆 · 附魔     │
│                                              │
│                                     言多必失榜│
│                                     1. 小闪 3 │
│                                     2. ad   1 │
│                                              │
└──────────────────────────────────────────────┘
```

| 位置 | 内容 |
| --- | --- |
| 左上 | 本轮全部危险词（词多自动折行） |
| 右上 | 倒计时 |
| **右侧中间** | **言多必失榜（谁死最多）**，宽度按内容自适应 |

> 1.0.7 修了榜单单面板行距算错、标题/名单/「共 N 次」三行叠在一起的问题。

> 右下角原来会显示「刚识别到什么」，1.0.6 起**去掉了**。

实现方式：服务端每秒把状态通过 `CustomPacketPayload` 推给客户端，
客户端用 `HudElementRegistry.addLast` 画在 HUD 上。
**判定永远在服务端** —— 客户端只负责画，改客户端免不了死。

配置里 `hudEnabled` 可关，`hudShowBoard` 控制榜单那一角。

### 言多必失榜

谁因为说错话死得最多就排前面，服务端累计统计（不按轮清零）。
网页上可以看前 10 名，也能一键清零。

## 7. 中文模型（重要）

## 7.1 模型怎么选（含「中英混说」的真相）

### Vosk 没有中英混合模型

官方 131 个模型，**每个都是单语言**（`vosk-model-small-cn-0.22` 只有中文词表）。
想在同一个模型里同时认中英文，Vosk 这条路走不通 —— 不是配置问题，是模型本身没有。

### 中文准确率可以换更大的模型

| 模型 | 大小 | 中文错误率 CER（SpeechIO-02） | 代价 |
| --- | --- | --- | --- |
| `vosk-model-small-cn-0.22`（现在） | 42MB | **23.54%** | 内存约 300MB，手机上都能跑 |
| `vosk-model-cn-0.22` | 1.3GB | **13.98%** | 官方建议按 16GB 内存预算，CPU 占用高 |

想试就改配置里的 `voskModel`：

```json
"voskModel": "vosk-model-cn-0.22"
```

它会自动下载（**1.3GB，按 100KB/s 算要 4 小时，建议睡前挂着**），
或者手动下 https://alphacephei.com/vosk/models/vosk-model-cn-0.22.zip
解压到 `<游戏目录>/shriek/vosk/vosk-model-cn-0.22/`。

> ⚠️ 大模型加载那一下会在渲染线程停 **十几秒**（无响应），属正常。
> 内存不够会直接 OOM。想回退：把 `voskModel` 改回 `vosk-model-small-cn-0.22`，删掉大模型目录即可。

### 真想要中英混合：只能换引擎

目前唯一现实的选择是 **SenseVoice**（小米，走 sherpa-onnx 的 Java API）：

| 项 | 情况 |
| --- | --- |
| 语言 | **中文 / 英文 / 日文 / 韩文 / 粤语，一个模型全包**，不用切语言 |
| 模型大小 | int8 量化约 **229MB** |
| 准确率 | 明显高于 Vosk 小模型（尤其带口音的英文、中英混说） |
| 热词 | 支持自定义热词表，可以直接把危险词灌进去 |
| 代价 | 要**重写整条识别管线**（SenseVoice 是非流式的，得先用 VAD 切句）；每人还要多下 ~250MB |

**我的建议**：先玩现在这版（1.0.14 加了多候选 + 更全的变体，成本为零）。
如果玩下来还是觉得「中英混说」是主要痛点，再让我做 SenseVoice 版本 —— 那是一次大改，要单独发一个 v2。

## 7.5 录音设备（1.0.13：游戏内切换，且下次启动自动记住）

游戏内按 **F8** 选设备，**点完立刻生效**，不用重启。
**下次开游戏会自动用这个设备**，不用再选一次（1.0.13 修的就是这个）。

启动时的行为：

| 配置里的 `audioDevice` | 启动后 |
| --- | --- |
| 空（系统默认） | 用 Shriek 原生那套，什么都不动 |
| 具体设备名 | 模型就绪后自动接管录音，日志有「启动自动接管录音结果：true」 |

> 1.0.12 及以前，设备名只是存进配置，重启后没有任何人读它 ——
> 所以你会看到「✔ 选好了，但还得再选一次才生效」。

### 怎么做到的：自己接管录音

参考了 Simple Voice Chat 的做法 —— 它之所以能热切换，是因为**麦克风是它自己开的**，
线程归它管，换设备就是关掉自己的线程再开。

Shriek 不肯给这个能力，但它留了三个公开入口，够我们搭一条自己的管线：

| 用到的 | 作用 |
| --- | --- |
| `SpeechRecognizer.getStringMsg(byte[])` | 识别音频（用它现成的识别器） |
| `PlayerSpeakPacket(String)` | 组装"我说了一句话"的包 |
| `ShriekPackets.sendToServer(...)` | 发出去 |

于是流程变成：**我们 open 设备 → 我们读 → 用它识别 → 用它通道发包**。
Shriek 只当"识别器 + 通道"，麦克风完全归我们。

切换设备 = `MicCapture.start(新设备)`：关掉自己的 line → join 自己的线程 → 开新设备。
自己的线程，join 一定拿得到，不存在之前"停不下来"的问题。

### 之前为什么一直失败

| 做法 | 结果 |
| --- | --- |
| Shriek 的 `resetListener()` 后等它重连 | 它**不会重连** |
| `loadVoskModel()` 重建识别器 | 和没退出的旧线程抢同一个识别器 → Vosk 原生断言，JVM 死 |
| Mixin 改它 `AudioSystem.getLine` | 正式环境不稳定，时好时坏 |
| **自己接管录音（现在）** | ✅ 实测两次热切换都成功 |

### 注意

- 选「系统默认」时不会接管，走 Shriek 原生那套，行为不变。
- 接管后如果识别异常，**重启游戏**即可回到原生。
- 接管时会把 Shriek 的重试定时器一起停掉，避免它抢设备。

## 8. 怎么玩（**要先 /start**）

模组**默认不启用** —— 进去不会自动开始，避免一进世界就被自己的话干掉。

1. 单人进世界（或者开个服）
2. 输入命令开始：

```
/voicekill start      ← 开始（别名 /vk start）
/voicekill stop       ← 停止
/voicekill status     ← 看当前状态
```

3. 屏幕左上变成「本轮危险词：小白 · ad · 岩浆 · …」
4. 浏览器开 `http://127.0.0.1:38471/`（可选，也可以在上面点「开始」）
5. 对着麦克风说出来
6. 1~2 秒后你死了，四角榜单 +1

**没 start 之前**：不计时、不换词、不判定、也不统计词频（四角只显示「未开始 · 输入 /voicekill start」）。

**注意**：因为每轮至少有一个「我 / 你 / 他」这类词，**基本上开口就死**。
觉得太狠就打开网页把「高频」配额拉到 0，或者把 `highFreqPerRound` 改成 0。

**换麦克风**：游戏里按 **F8**，选完立刻生效（不用重启）。也可以在「按键设置 → VoiceKill」里改键。

**识别延迟 1~2 秒是正常的**（Vosk 要等你说完一句才出结果），不是 bug。

```

├── VoiceKillMod.java              入口：配置、tick、S2C 通道注册、起网页
├── DangerWordManager.java         组词逻辑、轮换、智能选词、状态快照、HUD 广播
├── SpeechHandler.java             Shriek 事件 → 统计 → 判定 → kill → 记榜单
├── DeathBoard.java                言多必失榜
├── config/ModConfig.java          JSON 配置读写
├── speech/SpeechStats.java        中文 n-gram 分词 + 词频统计 + 碎片过滤
├── wordbank/WordBank.java         口语/正式/高频/人名 多层词库
├── util/TextUtil.java             归一化（匹配和统计共用）
├── util/WordAliases.java          英文缩写 → 谐音变体（ad → 哎弟）
├── network/HudStatePayload.java   S2C：四角要显示的东西
├── web/WebConsole.java            HTTP 服务（JDK 自带 HttpServer，零依赖）
├── mixin/MicrophoneHandlerMixin.java  重定向 Shriek 的录音设备选择
└── client/
    ├── VoiceKillClient.java       注册 HUD / 收包 / 准备模型 / 列设备
    ├── HudOverlay.java            四角渲染
    └── AudioDevices.java          录音设备枚举与选择
src/main/resources/voicekill/console.html   控制台页面（单文件，内联 CSS/JS）
src/main/resources/voicekill.mixins.json    Mixin 配置（required=false，坏了不影响启动）
```

**线程模型**（改代码前务必理解）：
MC 状态只在服务端逻辑线程改，网页线程只读「快照」，
所有网页写操作都通过 `server.execute()` 排队 —— 别在 HTTP handler 里直接碰游戏对象。

**没有自定义 C2S 数据包**：Shriek 已经铺好「客户端识别 → 发包 → 服务端事件」这条路了。

## 12. 已知限制

- **识别延迟 1~2 秒**，说完不会立刻死
- **Vosk 不准**：口音、麦克风音量、环境噪音都影响，说不清就多喊两遍
- **默认配置基本开口就死**（每轮有 1 个高频词），嫌狠就调 `highFreqPerRound`
- 智能选词的第一个周期没数据（还没人说话），只能从词库里随机
- 中文 n-gram 分词是**启发式**的，长句里偶尔还是会漏进一两个奇怪的组合词 ——
  看榜单觉得不对，点 `×` 删掉或者直接手动指定下一轮就行
- 一组的词之间**没有优先级**，命中任意一个都死，所以「我」在组里时其它 4 个基本没机会发挥
- **谐音自动生成只覆盖 ≤5 字符的纯英文/数字**，中文名谐音得手动配
- 换录音设备后要等十几秒才自动重连，期间不识别（Shriek 重试定时器的周期）
- 玩家在**旁观 / 创造**模式一样会被 kill（`/kill` 本身就这行为）
