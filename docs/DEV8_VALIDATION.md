# dev.8：以最终复核句判定，并修复高频词统计/匹配

## 复现证据与修复

玩家截图和本机日志对应同一段语音：原始识别为“好吃的”，两次复核为 `how much the shirt is`，accepted=true。旧实现把复核当附加候选，原始“好吃的”仍可匹配“吃的”，即使字幕已显示复核英文。这是候选判定问题，不是两句话显示时间不同。

新实现由已接受的复核决定本段判定和词频输入。被否定的原文/备用候选不独立处罚、不进后续拼接窗口。原文保留在日志/公告，有复核时公告另列复核句。若整段原文确实包含在最终句中，可按原有长名字窗口继续衔接；不会把新造出的复核文字加入历史。新增字母命中仍限精确，混合词中文仍须有原始依据；中文危险词必须在原始与最终句中都有匹配支持，避免纠错凭空增加中文/单字处罚。中文修改也做两次音频稳定性检查；这是同一模型的两次条件复核，并非保证正确的独立投票。

## 高频词审查

- 原 `SpeechHandler` 只统计首候选，现统一统计 `SpeechPacket.finalText()`，不再把已撤回的原始中文误识别写入频次。
- 原中文 2～4 字片段先整段计一次、n-gram 又计一次，导致短句双倍计数；现每次出现只计一次，换轮/累计桶规则不变。
- `highfreq` 和 `smart` 来源不自动生成中文同音别名，也不跨不同最终语句拼接；完整词在同一句正常命中。用户明确配置的别名保留。
- “我/你/他”等固定高频池是配额随机选取；动态统计有停用词过滤，这是原设计，不把两类混为一谈。单字仍不接受原始备用候选或仅复核新增的命中。
